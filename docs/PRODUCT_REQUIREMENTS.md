# 图片尺寸工具：第一版需求文档

## 1. 这份文档的用途

这是第一版已经确认范围的说明，用于后续开发、验收和扩展时保持边界一致。

## 2. 已确认的决定

| 问题 | 已确认做法 | 为什么这样定 |
| --- | --- | --- |
| 面向谁 | 所有使用英文的用户，优先跨境卖家 | 与网站的搜索词和核心用途一致 |
| 网站语言 | 第一版只有英文界面 | 与英文搜索流量匹配 |
| 服务地区 | Amazon 美国站、TikTok Shop 美国站；Shopify 面向所有店铺 | 三者都有清晰的英文用户群 |
| 一次处理多少张图 | 最多 10 张、每张不超过 25 MB | 能满足日常批量工作，也让浏览器本地生成 ZIP 时更稳定 |
| 收费 | 单张下载免费；批量 ZIP 下载为 $3.99/次 | 图片工具通常是偶尔使用，一次一付比订阅更直接 |
| 广告 | 正式域名上线并满足 Google AdSense 要求后展示广告 | 不在编辑操作区放干扰下载的广告 |
| 域名 | `opensourcephotoeditor.com` | 根域名会跳转至主要地址 `www.opensourcephotoeditor.com` |

## 3. 项目背景与目标

跨境卖家常常需要把同一张产品图制作成不同平台可用的尺寸。现有工具要么收费、要么要求上传原图。这个网站提供一个不需要注册的网页工具：图片只在用户自己的浏览器中打开、裁剪和导出，网站不会收到原图。

第一版的成功标准：

- 用户能在电脑或手机浏览器选择图片。
- 用户能为 Amazon、Shopify、TikTok Shop 选择尺寸模板，或填写自己的宽高。
- 用户能拖动图片、放大或缩小，决定裁剪范围。
- 用户能免费压缩并下载一张处理后的图片。
- 一次处理 2 到 10 张图片时，用户可支付 $3.99 下载一个 ZIP 压缩包。
- 全程不上传原图，也不建立用户账号。

## 4. 第一版用户范围

### 主要用户

独立站和电商平台卖家、运营人员、虚拟助理，以及偶尔要制作商品图的小团队。

### 典型使用过程

1. 用户打开网站首页，看到“图片不会上传”的说明。
2. 用户点击“Choose images”，选择一张或多张 JPG、PNG、WebP 图片。
3. 用户选择一个平台尺寸，或者填写宽与高。
4. 用户在预览区拖动、放大图片，让商品处在合适位置。
5. 用户选择 JPG 或 PNG，点击下载。
6. 浏览器生成文件并下载到用户电脑；原图从未离开设备。

## 5. 第一版要做的功能

### 5.1 选择图片

- 支持拖放图片和点击选择图片。
- 接受 JPG、PNG、WebP。
- 第一次提示支持的格式、最多 10 张、单张最多 25 MB。
- 选错文件、图片损坏或超出限制时，给出清楚的英文错误提示，不让页面崩溃。
- 第一版不承诺支持 HEIC、GIF、PSD、RAW 和 SVG。

### 5.2 平台尺寸模板

页面提供以下“常用尺寸”快捷按钮，所有尺寸都允许用户改成自定义值：

| 模板名称 | 暂定导出尺寸 | 说明 |
| --- | --- | --- |
| Amazon product image | 2000 x 2000 | 方形高分辨率商品图，利于缩放展示 |
| Shopify product image | 2048 x 2048 | 常用方形商品图 |
| TikTok Shop product image | 1080 x 1080 | 常用方形商品图 |
| Custom size | 用户填写 | 宽和高范围为 100 到 6000 像素 |

这些是制作模板，不是平台合规承诺。平台的图片规则可能变更，用户仍须按所在站点的最新规则发布。

### 5.3 裁剪与预览

- 单张编辑时显示固定比例的裁剪框。
- 用户能拖动图片的位置，使用滑杆或加减按钮放大、缩小。
- 用户可以旋转图片 90 度、恢复到初始状态、删除当前图片。
- 用户可在切换模板时看到裁剪框变化。
- 同时处理多张图片时，先编辑第一张；其余图片使用“居中裁剪”作为默认设置。用户可逐张调整。
- 预览只显示在本地浏览器，不使用网页服务器保存临时图片。

### 5.4 压缩、导出与下载

- 用户选择 JPG 或 PNG；JPG 默认质量为 90%，可调低质量来减小文件大小。
- 单张图片可以免费压缩、裁剪并下载。
- 多张图片可以选择和预览，但批量压缩与 ZIP 下载需支付 $3.99。未付款用户点击下载时，页面显示付款入口，不生成文件。
- 付款由 Stripe Checkout 完成。付款成功后，用户回到原编辑页下载一个 ZIP 压缩包；一次付款对应一次批量下载。
- 文件名默认保留原文件名，并加上平台和尺寸，例如 `lamp-amazon-2000x2000.jpg`。
- 所有导出都由浏览器在用户设备上生成。

### 5.5 广告与付费入口

- 首页内容区可以预留 Google AdSense 广告位，但编辑器的选图、裁剪和下载区域不展示插入式广告。
- 在 Google AdSense 审核通过前，不加载广告代码，也不显示假广告占位内容。
- 多张压缩的下载按钮显示 `Unlock batch for $3.99`，并在弹窗中打开 Stripe 的付款页。
- Pricing 页面说明单张免费、批量 ZIP 为 $3.99、每批最多 10 张，且没有订阅。

### 5.6 信任、说明与搜索入口

- 首页首屏清晰显示：`Your images stay on your device.`
- 编辑页面显示简短的本地处理说明和隐私政策链接。
- 首页介绍三种模板及工具使用方式；不把工具包装成“官方 Amazon/Shopify/TikTok Shop 工具”。
- 提供 Privacy、Terms、Contact 页面。
- 提供可被搜索引擎读取的首页文字、页面标题和站点地图。

## 6. 第一版明确不做的事

以下功能不纳入第一版，防止上线被不必要的复杂度拖慢：

- 去背景、白底、抠图、加水印、滤镜和 AI 生成图片。
- 用户登录、保存历史、云端相册和团队协作。
- 用户账号、订阅、折扣码、续费和自动退款不进入第一版。
- 直接发布图片到 Amazon、Shopify 或 TikTok Shop。
- 平台规则自动审核或“保证通过审核”。
- 服务端保存、备份、分析或人工查看用户原图。
- HEIC、PSD、RAW、GIF、视频等格式。

## 7. 图片隐私的硬性要求

这是本项目的核心承诺，不能因统计、广告或未来收费而被破坏：

1. 用户选择的图片只能用浏览器本身读取和处理。
2. 前端代码不得把图片文件、图片内容或预览图发送到任何网址。
3. 不使用图片上传接口、对象存储、数据库或第三方图片处理服务。
4. 即使接入访问量统计，也只记录页面访问和按钮点击等不含图片内容的信息。
5. 隐私页面要如实说明：关闭网页或刷新页面后，未下载的处理结果会消失。

## 9. 技术选择

| 部分 | 选择 | 简单解释 |
| --- | --- | --- |
| 网站基础 | Next.js + TypeScript | 一套常见、稳定的网站制作方式，适合 Vercel |
| 页面样式 | 原生 CSS | 更少依赖，仍能做出手机和电脑都能使用的界面 |
| 图片裁剪 | 浏览器 Canvas API | 浏览器自带的图片处理能力，不需要上传图片 |
| 多图压缩包 | fflate | 在浏览器本地生成 ZIP 文件 |
| 收款 | Stripe Checkout + Vercel 接口 | Stripe 接收付款资料；Vercel 只创建和核验订单，不接收图片 |
| 发布平台 | Vercel | 连接代码仓库后可自动发布网站 |
| 搜索设置 | `sitemap.ts` 与 `robots.ts` | 自动生成搜索引擎需要的站点文件 |
| 付款资料处理 | Stripe | 由持牌收款服务处理银行卡资料，不接触用户的图片 |

内容页面保持静态；只有创建和核验 Stripe 订单的三个小接口会按请求运行。它们不接收图片文件，也不访问图片内容。

## 10. 界面原则

- 先让用户选图，再让用户选尺寸；不要一开始塞满选项。
- 主要按钮只用清楚的动作词：Choose images、Download、Reset。
- 手机上仍可完成完整流程；编辑预览区要随屏幕缩小。
- 工具界面避免广告式大段文字，重点是连续完成“选图、裁剪、下载”。
- 不用“100% 平台合规”“官方”等无法证明的宣传语。

- 功能已在真实网址可用。
- 网站已发布到 Vercel。

## 13. 关于 `open source photo editor` 这个关键词

代码已推送到 GitHub，但仓库中目前没有 `LICENSE` 文件。仅把代码放到 GitHub 并不等于授予他人开源使用许可，因此网站现在仍不应把自己描述成“open source photo editor”。只在网页标题或正文中堆这个词，会伤害用户信任，也可能让搜索引擎判断页面不匹配搜索意图。

有两个诚实的选择：

1. 把基础裁剪工具发布到公开 GitHub 仓库，并使用 MIT 许可证。这样可以真实地使用“open source”描述基础工具；收入来自广告、已托管的网站和 Pro 批量功能。
2. 不公开代码。这样首页和工具页应使用 `private browser image cropper`、`Amazon image resizer` 等更准确的词；`open source photo editor` 只用于一篇比较文章，介绍开源工具与本地浏览器处理的不同。

第一种更符合当前关键词，但需要你确认愿意公开基础代码，并加入合适的开源许可证。第二种更适合保留全部代码和产品功能的控制权。
